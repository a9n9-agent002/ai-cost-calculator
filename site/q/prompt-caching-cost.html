Prompt caching cost: the same model's cached token is up to 52x dearer at one provider

Prompt caching is sold as a discount on input tokens, and inside one vendor it is: Novita's own table cuts input by 5.45x at the median, from 2.00x (DeepSeek R1 0528: $0.70 to $0.35) to 120.83x (MiMo V2.6 Pro: $0.435 to $0.0036). But a cached token is only cheaper than a fresh token at the same provider. Across the 34 models all three providers serve, 26 quote a cached-read price and 21 of them disagree: GLM 5.2 reads cache at $0.26 a million at Novita and $0.005 at OpenRouter, a 52.0x spread for identical weights. That matters because the expensive end is dearer than paying no cache at all somewhere else: Novita's cached GLM 5.2 rate is 43.33x OpenRouter's uncached input price of $0.006.

What the cache actually discounts

A cache price is a read price for a prefix the provider kept. Novita publishes one for 48 of its 76 priced models; the other 28 have no cached-read price at all, so on 37% of the catalogue caching is not a lever you can pull. Where it exists, the ratio of input to cached input is what your bill sees, and it is not a constant: the same vendor discounts 121x on MiMo V2.6 Pro and 2.00x on DeepSeek R1 0528.

Where the cache is still the right lever

Turned the other way, the same table is the argument for caching at the cheaper vendor. On the 23 models where Novita quotes a cached-read price and a rival quotes an uncached one, Novita's cached token is cheaper than the rival's fresh token on 19 of 23 — and dearer on 4, which the table above names. A merit claim is only worth printing with its counter-example beside it.

The break-even most guides skip

Caching pays when the prefix is re-read. With the cache written at the input rate (the assumption these three providers' pages support: none of them publishes a separate write premium here), a cached read at any discount beats an uncached one from the first re-read. Charge 1.25x to write the cache — the premium some providers do publish — and the re-reads needed are 0.25 / (1 - cached/input): for the 2.00x row above that is half a re-read, so the first repeat use still pays. The premium is never what decides it on these rows; reuse is. A prefix used once is a write with no read, and it bills at the input rate plus whatever the write premium adds.
